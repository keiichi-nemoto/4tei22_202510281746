CLAUDE CODE 入門

Sub-agents と Skills
しくみと使い方

「部下に任せる」と「手順書を渡す」── 2つの拡張機能をやさしく解説

Claude Code には、作業を賢く広げる2つの仕組みがあります。

それが「Sub-agents（サブエージェント）」と「Skills（スキル）」です。

OVERVIEW

ひとことで言うと

🧑‍💼

Sub-agent

専門の「部下」
別の作業部屋（コンテキスト）で仕事をして、結果だけを報告

📘

Skill

必要なときに開く「手順書」
Claude 自身が読み込んで、そのやり方で作業する

サブエージェントは、仕事を任せられる専門の「部下」です。

スキルは、必要なときだけ開く「手順書」や「マニュアル」です。

まずはサブエージェントの仕組みから見ていきましょう。

SUB-AGENTS ① しくみ

仕事を「別の部屋」に任せる

🤖 メインの Claude
あなたと会話中
① タスクを依頼「認証まわりのコードを調べて」
③ 要約した結果だけを返す
🧑‍💼 Sub-agent
専用のコンテキスト
② サブエージェントの部屋の中で…
ファイルを 30 個読む / grep を何度も実行 / 試行錯誤
→ この大量のログはメインに持ち込まれない

メインの Claude は、タスクをサブエージェントに依頼できます。

サブエージェントは自分専用のコンテキストで、たくさんのファイルを読んだり調べたりします。

そして、最後に要約した結果だけをメインに返します。

途中の大量のやり取りでメインの会話が埋まらない、これが最大のポイントです。

SUB-AGENTS ② メリット

なぜ便利なのか

🧹 コンテキスト節約
調査の途中経過でメインの会話が散らからない

⚡ 並列実行
複数のサブエージェントを同時に走らせられる

🔒 ツールを制限
「読むだけ」など使えるツールを絞って安全に

🎯 専門化
役割ごとの指示・モデルを固定して品質を安定

メリットの1つ目は、メインのコンテキストを節約できることです。

2つ目は、複数のサブエージェントを並列に動かせることです。

3つ目は、使えるツールを制限して安全に任せられることです。

4つ目は、役割ごとに専用の指示やモデルを決めて、品質を安定させられることです。

SUB-AGENTS ③ 作り方

Markdown ファイル 1 つで定義

# .claude/agents/code-reviewer.md
---
name: code-reviewer
description: コード変更後のレビュー担当。
  変更を加えたら積極的に使うこと。
tools: Read, Grep, Glob, Bash
model: sonnet
---
あなたは経験豊富なレビュアーです。
git diff を確認し、バグ・可読性・
セキュリティの観点で指摘してください。
name … 呼び出し名
description … いつ使うか。
Claude はこれを見て任せるか判断
tools / model … 使えるツール・モデル（省略可）
本文 … サブエージェント専用のシステムプロンプト

サブエージェントは、Markdown ファイル1つで作れます。

先頭の設定部分に、名前を書きます。

description には「いつ使うか」を書きます。Claude はここを読んで、任せるかどうかを判断します。

tools と model で、使えるツールとモデルを指定できます。

本文は、そのサブエージェント専用のシステムプロンプトになります。

SUB-AGENTS ④ 使い方

置き場所と呼び出し方

置き場所
📁 .claude/agents/ … プロジェクト用（チームで共有）
📁 ~/.claude/agents/ … 自分用（全プロジェクト）
/agents コマンド
対話形式で作成・編集・ツール設定ができる
① 自動で任せる
description に合うタスクなら Claude が自分で委任
② 名前を指定して頼む
「code-reviewer サブエージェントで
今の変更をレビューして」
組み込み: Explore（調査）Plan（計画）general-purpose

ファイルはプロジェクトの .claude/agents か、ホームの ~/.claude/agents に置きます。

/agents コマンドを使えば、対話形式で作成や編集ができます。

description に合う仕事なら、Claude が自動で任せてくれます。

もちろん、名前を指定して明示的に頼むこともできます。

また、調査用の Explore や計画用の Plan など、組み込みのサブエージェントも用意されています。

SKILLS ① しくみ

必要なときだけ読み込む「手順書」

1
名前と説明だけを常に把握 … 起動時。とても軽い
2
関係ありそうなら SKILL.md 本文を読む … 必要になった時
3
さらに必要なら 参考資料・スクリプトを使う … 段階的に

次はスキルです。スキルは「段階的に読み込まれる手順書」です。

Claude は最初、各スキルの名前と短い説明だけを知っています。

タスクに関係があると判断したときに、初めて SKILL.md の本文を読み込みます。

さらに必要なら、同じフォルダの資料やスクリプトも使います。

だから、スキルをたくさん入れてもコンテキストをほとんど消費しません。

SKILLS ② 作り方

フォルダ ＋ SKILL.md

# フォルダ構成
.claude/skills/
└─ release-notes/
   ├─ SKILL.md
   ├─ template.md
   └─ scripts/
      └─ collect.sh
# SKILL.md
---
name: release-notes
description: リリースノートを作成する。
  「リリースノート」「変更履歴」と
  言われたときに使う。
---
1. scripts/collect.sh でコミットを集める
2. template.md の形式で整理する
3. 新機能 / 修正 / 破壊的変更 に分類

スキルは、フォルダと SKILL.md というファイルで作ります。

SKILL.md の先頭には、名前と説明を書きます。

説明には「何をするか」と「いつ使うか」を具体的に書くのがコツです。

本文には手順を書き、テンプレートやスクリプトを同じフォルダに置いて参照できます。

SKILLS ③ 使い方

置き場所と呼び出し方

置き場所
📁 .claude/skills/ … プロジェクト
📁 ~/.claude/skills/ … 個人
🧩 プラグイン … 配布・共有
① 自動で使われる
「今回のリリースノート作って」
→ 説明が合うスキルを Claude が選ぶ
② スラッシュで直接呼ぶ
/release-notes

スキルの置き場所は、プロジェクト用、個人用、そしてプラグインの3種類です。

普通に話しかけるだけで、説明が合うスキルを Claude が自動で使います。

スラッシュとスキル名を入力して、直接呼び出すこともできます。

COMPARE

違いと使い分け

🧑‍💼 Sub-agent📘 Skill
正体別コンテキストで動く「部下」Claude が読む「手順書」
コンテキスト分離される（結果だけ戻る）メインに読み込まれる
ファイル.claude/agents/名前.md.claude/skills/名前/SKILL.md
向いている仕事大量の調査・レビュー・並列作業決まった手順・社内ルール・定型作業

2つを比べてみましょう。サブエージェントは部下、スキルは手順書です。

サブエージェントはコンテキストが分離され、スキルはメインに読み込まれます。

ファイルの置き場所と形も少し違います。

大量の調査や並列作業はサブエージェント、

決まった手順やルールを守らせたいときはスキル、と使い分けましょう。

SUMMARY

まとめ ── 今日からできること

✅ 調べ物が多いときは「サブエージェントで調べて」と頼む
✅ /agents で、レビュー担当など自分のチーム用の部下を作る
✅ 何度も説明している手順は SKILL.md に書いてスキル化する

組み合わせも可能：サブエージェントの中でスキルを使う、など

まず、調べ物が多いときはサブエージェントに任せてみましょう。

次に、/agents コマンドで自分専用の部下を作ってみましょう。

そして、何度も説明している手順は、スキルにまとめましょう。

2つを組み合わせれば、Claude Code はもっと頼れる相棒になります。
